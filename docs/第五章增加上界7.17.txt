可以做，而且**净利润上下界会明显增强论文的说服力**。但必须先明确：

> **Only-home和Only-meeting-points不能直接作为净利润的数学上下界。**

它们只能称为“极端服务政策参照”。当前RC结果中，Only-home净利润为1590.92，Only-meeting-points为1780.39，而DRPO达到2346.10，已经高于两者，所以Only-meeting-points显然不能作为净利润上界。

真正的上下界应按照优化问题的定义构造。

## 一、净利润上下界的基本逻辑

你的问题是最大化净利润。设最优净利润为 (V^*)，则有：

[
\underbrace{V(\pi)}*{\text{可行策略利润，下界}}
\leq
\underbrace{V^*}*{\text{真实最优利润}}
\leq
\underbrace{V^{UB}}_{\text{松弛或完全信息问题，上界}}
]

其中：

* 任何满足全部约束的可行策略，都能提供一个净利润下界；
* 放宽约束、增加信息或者扩大可行域得到的最优目标值，可以提供上界。

因此，在一个固定需求场景中：

* DRPO得到的可行净利润可以作为下界；
* DSPO、Static-pricing等也分别是可行下界；
* 所有可行方法中净利润最高的结果，是当前最佳下界；
* 完全信息或数学松弛模型提供上界。

当前六策略中，DRPO的平均净利润2346.10是**测试策略中的最佳可行结果**，但还不能称为真实最优值。

---

# 二、最适合你论文的净利润上界

## 方案一：完全信息离线Oracle上界

这是最推荐的方案。

现有DRPO是在线策略。在乘客到达前，它不知道：

* 后续还会来多少乘客；
* 后续乘客的位置；
* 后续乘客类型；
* 后续乘客的选择偏好；
* 未来车辆路线如何变化。

可以额外构造一个**完全信息离线Oracle**：

> 假设运营商提前知道整个运营周期内的全部乘客请求、位置、到达顺序、乘客类型和选择结果，然后联合优化集合点推荐、价格和车辆运营。

因为Oracle拥有比DRPO更多的未来信息，所以：

[
V^{Online*}\leq V^{Perfect\ Information}
]

只要该离线问题被精确求解，Oracle净利润就是在线问题的有效上界。

这能够让你报告：

[
Optimality\ Gap_{\mathrm{DRPO}}
===============================

\frac{UB-V_{\mathrm{DRPO}}}{|UB|}\times100%
]

例如论文中可以形成这样的结论：

> DRPO在不知道未来需求的在线条件下，取得了完全信息离线上界的某个百分比，平均最优性差距为若干百分点。

这个结论远强于单纯写：

> DRPO优于DSPO 6.94%。

它可以进一步说明：

> DRPO不仅优于现有基准，而且已经接近理论上可获得的利润水平。

当然，具体差距必须通过实验计算，不能预设。

---

## 方案二：使用精确求解器的最优界

如果你的模型可以写成MIP或其他精确优化模型，可以在小规模RC实例上使用Gurobi或CPLEX。

求解器会同时报告：

* incumbent：当前找到的最佳可行解；
* best bound：求解器证明的目标上界；
* MIP gap：两者之间的差距。

对于最大化问题：

[
LB=\text{best feasible incumbent}
]

[
UB=\text{solver best bound}
]

即使在规定时间内没有求到全局最优，求解器仍然可能给出有效上下界。

例如：

| 场景         | 最佳可行利润LB | 求解器上界UB | MIP gap | DRPO利润 | DRPO距上界 |
| ---------- | -------: | ------: | ------: | -----: | ------: |
| RC-small-1 |      待计算 |     待计算 |     待计算 |    待计算 |     待计算 |
| RC-small-2 |      待计算 |     待计算 |     待计算 |    待计算 |     待计算 |

这种设计非常适合你的论文：

* 小规模实例用精确算法得到上下界；
* 大规模实例用DRPO在线运行；
* 证明DRPO既有计算可扩展性，又接近小规模最优结果。

如果离线Oracle只用启发式算法求解，而且没有可证明的最优界，那么它只能称为“Oracle benchmark”或“best-known solution”，不能称为严格数学上界。

---

## 方案三：构造松弛模型上界

如果完整离线模型太复杂，可以放松部分约束，例如：

* 允许乘客分数分配；
* 放松0-1决策变量；
* 暂时忽略部分车辆容量约束；
* 放松时间窗；
* 取消在线非前视约束；
* 使用理想化最低插入成本；
* 允许车辆路线在需求全部已知后统一规划。

放松后，可行域扩大，因此对于最大化问题：

[
V^*\leq V^{Relaxation}
]

该松弛问题的最优值就可以作为净利润上界。

但要注意：放松得太强，上界可能非常宽。例如忽略车辆容量、时间和路径耦合后，上界会高得不具有比较意义。

最好的松弛应该：

* 保留乘客选择模型；
* 保留收入和价格边界；
* 保留主要车辆成本；
* 只放松最难处理的在线性、整数性或路径耦合。

# 三、下界怎样定义最合理

在固定需求实现下，任何可行政策的净利润都是下界。

当前可以定义：

[
LB_{\omega}
===========

\max{
\Pi_{\mathrm{Only-home}},
\Pi_{\mathrm{Only-MP}},
\Pi_{\mathrm{No-pricing}},
\Pi_{\mathrm{Static}},
\Pi_{\mathrm{DSPO}},
\Pi_{\mathrm{DRPO}}
}
]

在当前平均结果中，DRPO净利润最高，为2346.10，因此它是六个测试政策中的最佳经验下界。

但正式计算时，应该在每个相同种子上分别取值，而不是直接用六个策略平均值的最大值。

对于种子 (s)：

[
LB_s=\max_{\pi\in\mathcal P}\Pi_{\pi,s}
]

然后报告：

* 各方法平均净利润；
* 各方法距离上界的平均差距；
* 各方法达到最佳下界的次数；
* DRPO距离Oracle上界的平均百分比；
* 30个种子差距的95%置信区间。

---

# 四、必须加服务质量约束

净利润上界不能只追求利润，而忽视退出率。

你的Only-meeting-points结果已经说明：极端降低服务成本可能导致45.23%的乘客退出。北京/燕郊案例中，该策略退出率甚至达到52.63%。

因此，更合理的是构造**服务质量约束下的利润上界**：

[
\max \quad \mathbb E[\Pi]
]

满足：

[
QuitRate\leq \bar q
]

以及：

[
a_{tk}\in[\underline a,\overline a]
]

[
\text{车辆容量、路径、时间和服务约束}
]

其中 (\bar q) 可以设置为：

* 5%；
* 10%；
* 或者根据论文的服务标准设定多个阈值。

这样得到的上界是：

> 在退出率受到控制的情况下，系统最多能够获得多少净利润。

这比没有服务约束的利润上界更符合公共交通研究。

建议至少报告三个服务阈值：

[
\bar q\in{2%,5%,10%}
]

这样可以形成“利润—乘客留存前沿”，避免审稿人认为5%是为了突出DRPO而人为选择的阈值。

---

# 五、Only-home和Only-meeting-points可以怎样使用

它们可以被称为：

* service-mode extremes；
* operational reference policies；
* convenience and efficiency reference points；
* empirical reference envelope。

不能称为：

* theoretical lower bound；
* theoretical upper bound；
* optimal profit bound。

更准确的表达是：

> Only-home and Only-meeting-points define two extreme service configurations rather than mathematical profit bounds. Only-home represents the convenience-oriented extreme, whereas Only-meeting-points represents a cost-oriented extreme accompanied by substantial passenger abandonment.

也就是说，它们描述的是**服务模式边界**，而不是净利润边界。

这是一个联合选择、定价和车辆路径优化问题。完整RC规模下直接精确求解的组合数量极大。正确实验设计是求解8—20名乘客的小规模RC子实例，然后比较DRPO、DSPO与完全信息最优解的净利润差距。

# 一、先区分两个不同的“Oracle”

你的论文当前已经有一个所谓的真实成本定价Oracle：

[
\max_{\boldsymbol a_t}
\sum_{k\in O_t}
(f_e+a_{tk}-c_{tk})P_{tk}(\boldsymbol a_t).
]

它假设当前乘客每个上车选项的真实边际成本 (c_{tk}) 已知，然后为当前乘客求最优价格。DRPO则用预测成本 (\hat c_{tk}) 替代真实成本。

这个Oracle适合计算：

[
\text{pricing regret}
=====================

R(a^*(c);c)-R(a^*(\hat c);c),
]

也就是“预测成本导致的价格决策损失”。这正是SPO/SPO+最直接的决策质量指标。

但它**不是整个运营周期净利润的全局上界**，原因是：

1. 它还是逐名乘客求价格；
2. 它没有联合优化所有乘客；
3. 它没有提前联合决定所有上车位置；
4. 当前真实边际成本标签来自最终路线的反事实计算；
5. 当前终端路径采用的是贪心最近插入加2-opt，而不是精确路径最优解。

所以论文中应该区分：

> **True-cost pricing oracle**：衡量SPO的直接定价质量。

> **Perfect-information offline optimum**：衡量最终净利润距离完全信息最优结果还有多远。

这两个实验都很有价值，但作用不同。

# 二、在你的案例中，完全信息离线模型到底优化什么

对于一个给定的RC测试种子，离线模型提前知道：

* 当天所有乘客的到达；
* 每名乘客的居住位置；
* 每名乘客可以使用的集合点；
* 每名乘客的行为参数；
* 全部行驶距离和时间；
* 乘客随机效用扰动；
* 车辆数量和容量；
* 所有未来请求。

它同时决定：

1. 每名乘客看到的价格；
2. 每名乘客最终选择居家、哪个集合点或退出；
3. 每辆车服务哪些乘客；
4. 每辆车按照什么顺序访问上车节点；
5. 最终总净利润。

目标函数就是：

[
\max\quad
\text{总票价收入}
------------

## \text{总时间成本}

\text{总距离成本}.
]

与你论文的终端净利润定义完全一致。你的MDP中，当前阶段获得票价收入，终端阶段承担最终路径成本；Bellman方程也是以这一结构建立的。

# 三、最适合你的精确模型结构

## 1. 乘客选择变量

定义：

[
x_{tk}=
\begin{cases}
1,&\text{乘客 }t\text{选择内部选项 }k,\
0,&\text{否则},
\end{cases}
]

其中 (k) 可以是：

* 居家上车 (h_t)；
* 候选集合点 (m\in M_t)。

再定义：

[
x_{t0}=1
]

表示乘客退出。

每名乘客只能有一个结果：

[
x_{t0}+\sum_{k\in O_t}x_{tk}=1.
]

---

## 2. 价格变量

对每名乘客和每个内部选项设置价格调整：

[
-10\le a_{tk}\le10.
]

最终票价是：

[
f_e+a_{tk}.
]

其中：

* (a_{tk}>0)：附加费；
* (a_{tk}<0)：折扣。

这与你当前在线定价模型的价格范围和符号定义一致。

---

## 3. 乘客选择约束

你的乘客效用为：

[
U_{tk}
======

-\beta^{ivt}\tau_{tk}
-\beta^{walk}d_{tk}
-\beta^{price}a_{tk}
+\varepsilon_{tk},
]

外部选项效用为：

[
U_{t0}=V_0+\varepsilon_{t0}.
]

MNL模型可以等价解释为：每名乘客选择随机效用最高的选项。

在完全信息场景中，提前固定每名乘客的Gumbel随机误差：

[
\varepsilon_{tk},\qquad \varepsilon_{t0}.
]

若 (x_{tk}=1)，则必须保证该选项效用最高：

[
U_{tk}\ge U_{tj},
\qquad \forall j\in O_t,
]

以及：

[
U_{tk}\ge U_{t0}.
]

使用Big-(M)可写为：

[
U_{tk}
\ge
U_{tj}-M(1-x_{tk}),
]

[
U_{tk}
\ge
U_{t0}-M(1-x_{tk}).
]

如果乘客退出，即 (x_{t0}=1)，则：

[
U_{t0}
\ge
U_{tk}-M(1-x_{t0}),
\qquad \forall k\in O_t.
]

这些约束都是价格变量的线性约束，因为价格只通过

[
-\beta^{price}a_{tk}
]

进入效用。

这一步非常关键：**固定随机效用扰动以后，原来的概率选择问题就变成了确定性选择约束。**

---

## 4. 收入线性化

票价收入为：

[
\sum_t\sum_{k\in O_t}
(f_e+a_{tk})x_{tk}.
]

这里存在乘积：

[
a_{tk}x_{tk}.
]

定义辅助变量：

[
q_{tk}=a_{tk}x_{tk},
]

利用价格上下界即可进行标准线性化。例如当(\underline a=-10,\overline a=10)时：

[
q_{tk}\le \overline a x_{tk},
]

[
q_{tk}\ge \underline a x_{tk},
]

[
q_{tk}\le a_{tk}-\underline a(1-x_{tk}),
]

[
q_{tk}\ge a_{tk}-\overline a(1-x_{tk}).
]

总收入变为：

[
\sum_t\sum_{k\in O_t}
\left(f_ex_{tk}+q_{tk}\right).
]

---

## 5. 路径变量

设：

[
y_{vij}=1
]

表示车辆 (v) 从上车节点 (i) 行驶到节点 (j)。

还需要定义乘客—车辆分配变量：

[
z_{tkv}=1
]

表示乘客 (t) 选择选项 (k)，并由车辆 (v) 服务。

满足：

[
\sum_v z_{tkv}=x_{tk}.
]

车辆容量约束为：

[
\sum_t\sum_{k\in O_t}z_{tkv}\le Q_v.
]

路径部分加入：

* 节点访问约束；
* 流量守恒约束；
* 车辆容量约束；
* 子环消除约束；
* 起点和共同终点约束；
* 同一集合点多名乘客共享访问节点的连接约束。

由于你的场景是many-to-one，所有乘客最终去往同一个目的地，路径结构比一般many-to-many DRT简单。它本质上是带可选上车节点和乘客选择的多车辆路径问题。

---

## 6. 完整净利润目标

完全信息模型的目标可以写成：

[
\max
\left[
\sum_t\sum_{k\in O_t}
(f_ex_{tk}+q_{tk})
------------------

c_\omega
\left(
\sum_v\sum_{i,j}\omega_{ij}y_{vij}
+
\sum_i l_iY_i
\right)
-------

c_f\sum_v\sum_{i,j}d_{ij}y_{vij}
\right].
]

其中：

* (Y_i=1)表示节点 (i)被访问；
* (\omega_{ij})为行驶时间；
* (d_{ij})为行驶距离；
* (l_i)为停站时间；
* (c_\omega)为单位时间成本；
* (c_f)为单位距离成本。

这与当前论文的终端路径成本定义保持一致。

# 四、在RC案例中具体怎样生成小规模实例

你当前RC数据包含200个空间位置，训练集和测试集各100个位置，候选集合点数量为10。原始RC设置平均约90个请求，并配置9辆车、每辆车容量10。这个完整规模用于在线算法比较是合适的，但不适合联合精确求解。 

建议从现有30个RC评价种子中抽取以下规模：

| 规模 | 请求数 | 每名乘客集合点选项 | 车辆数 |     容量 |
| -- | --: | --------: | --: | -----: |
| XS |   8 |      最近2个 | 1—2 | 沿用RC比例 |
| S  |  12 |      最近2个 |   2 | 沿用RC比例 |
| M  |  16 |      最近3个 | 2—3 | 沿用RC比例 |
| L  |  20 |      最近3个 |   3 | 沿用RC比例 |

每个规模建议使用：

* 10个独立测试种子作为基本版本；
* 20个种子作为正式论文版本。

每个子实例都必须直接来自现有RC测试位置和参数，不能重新创造一套与主实验无关的数据。

例如，对一个12请求子实例：

1. 使用RC测试种子生成当天全部请求；
2. 按到达顺序取前12名乘客；
3. 为每名乘客保留居家位置和最近2个集合点；
4. 固定行为参数；
5. 固定乘客随机效用扰动；
6. 使用相同价格范围；
7. 使用相同车辆速度、工资、燃油成本和停站时间；
8. 分别运行Static、DSPO、DRPO；
9. 再运行完全信息精确模型；
10. 用相同数据重新计算所有方法的最终路径成本和净利润。

# 五、当前路径求解器必须更换

你当前用于反事实边际成本标签的终端路径求解器是：

> greedy nearest insertion + 2-opt。

这个算法可以快速得到较好路线，但不能证明路线是全局最优。

因此，完全信息实验中不能继续用该启发式求解器，然后称结果为“精确上界”。

小规模Oracle必须采用：

* Gurobi精确MIP；
* CPLEX精确MIP；
* 或精确动态规划/分支定界。

求解器需要报告：

* 最优目标值；
* best bound；
* MIP gap；
* 求解时间；
* 是否在时限内证明最优。

建议设置：

[
\text{MIPGap}=0
]

或至少：

[
\text{MIPGap}\le0.1%.
]

如果在给定时限内未证明最优，就报告：

* 当前最佳可行净利润；
* 求解器上界；
* 剩余gap。

此时仍然可以用求解器的best bound作为严格上界。

# 六、一个重要问题：完全信息要知道乘客是否会退出吗

要知道，而且需要固定每名乘客的随机效用扰动。

你的在线仿真使用MNL概率随机生成选择。若离线模型只知道乘客位置，却不知道随机选择结果，它求的是期望优化问题，模型会变成带指数函数的非线性优化，精确求解难度大幅提高。

最干净的做法是使用MNL的随机效用表示：

[
U_{tk}=\bar U_{tk}+\varepsilon_{tk},
]

其中(\varepsilon_{tk})服从Gumbel分布。

对于每个种子：

1. 预先生成并保存所有(\varepsilon_{tk})；
2. DSPO和DRPO使用同一组随机效用扰动；
3. 完全信息Oracle也使用同一组扰动；
4. Oracle提前看到这些扰动；
5. Oracle通过价格决定每名乘客最终选择哪个选项。

这样Oracle拥有比在线策略更多的信息，故：

[
\Pi^{DRPO}_s
\le
\Pi^{PI}_s.
]

这里的(\Pi^{PI}_s)就是场景 (s) 的完全信息净利润上界。

---

# 七、需要设置退出率约束吗

建议同时计算两个Oracle。

## 1. 纯净利润Oracle

[
\max \Pi
]

不限制退出率。

它回答：

> 如果运营商只追求净利润，在完全知道未来和乘客选择冲击时，最多能赚多少钱？

这个Oracle可能会主动通过高价让高成本乘客退出。

## 2. 服务约束Oracle

增加：

[
\sum_t x_{t0}\le \bar qN.
]

例如：

[
\bar q\in{5%,10%}.
]

它回答：

> 在至少服务95%或90%乘客的条件下，最多能够实现多少净利润？

你的论文核心是净利润、运营成本和乘客退出率之间的权衡，因此**服务约束Oracle更有解释力**。

对于小规模请求数，可以使用整数约束：

| 请求数 | 5%退出约束 |
| --: | -----: |
|   8 | 最多0人退出 |
|  12 | 最多0人退出 |
|  16 | 最多0人退出 |
|  20 | 最多1人退出 |

为了避免小实例下5%过于严格，也可以统一报告：

* 无退出约束；
* 最多1人退出；
* 最多2人退出。

# 八、最终怎样与DRPO比较

对于每个测试场景 (s)，计算：

[
Gap^{DRPO}_s
============

\frac{
\Pi^{PI}_s-\Pi^{DRPO}_s
}{
|\Pi^{PI}_s|
}
\times100%.
]

同样计算：

[
Gap^{DSPO}_s
============

\frac{
\Pi^{PI}_s-\Pi^{DSPO}_s
}{
|\Pi^{PI}_s|
}
\times100%.
]

还可以定义“DRPO缩小了多少最优差距”：

[
GapReduction_s
==============

\frac{
Gap^{DSPO}_s-Gap^{DRPO}_s
}{
Gap^{DSPO}_s
}
\times100%.
]

最终表格可以这样设计：

| 请求数 | 完全信息上界 | Static利润 | DSPO利润 | DRPO利润 | DSPO gap | DRPO gap | 求解时间 |
| --: | -----: | -------: | -----: | -----: | -------: | -------: | ---: |
|   8 |        |          |        |        |          |          |      |
|  12 |        |          |        |        |          |          |      |
|  16 |        |          |        |        |          |          |      |
|  20 |        |          |        |        |          |          |      |

正文重点看两件事：

1. DRPO是否始终比DSPO更接近完全信息上界；
2. 随着请求规模增加，DRPO的相对gap是否保持稳定。

# 九、预计能精确求解到多大

根据你当前问题结构，合理预期是：

* 8名乘客：很容易精确求解；
* 12名乘客：通常可以稳定求解；
* 16名乘客：适合作为主要精确实例；
* 20名乘客：可以尝试，求解时间取决于车辆数、候选集合点和重复节点；
* 30名以上：联合定价、选择和多车辆路径的精确求解会明显变慢；
* 完整约90请求RC：不作为精确求解目标。

真正影响规模的不是200个RC地理位置，因为每个小实例只会激活其中少量乘客位置和集合点。主要复杂度来自：

[
\text{乘客数}
\times
\text{候选选项数}
\times
\text{车辆路径组合}.
]

所以将每名乘客的集合点选项从10个压缩为最近2—3个，是必要且合理的。你的在线框架本身也是先生成有限候选集合点，再执行预测和定价。

# 十、这个实验是否值得补

值得，但应明确它在论文中的位置。

你当前最直接的SPO证据仍然是：

[
\text{DSPO vs DRPO}
]

以及：

* 配对净利润差；
* SPO pricing regret；
* 预测误差；
* 定价一致率。

完全信息小规模实验进一步回答：

> DRPO取得的净利润距离可达到的理想水平还有多远？

建议最终形成三层证据：

### 第一层：六策略主实验

证明DRPO在实际政策基准中实现最高净利润和良好服务权衡。

### 第二层：DSPO—DRPO配对实验

证明SPO/SPO+训练带来增量价值。

### 第三层：小规模完全信息上界

证明DRPO比DSPO更接近完全信息最优净利润。

这样论文的证据链会非常完整：

[
\text{SPO训练}
\rightarrow
\text{更低定价遗憾}
\rightarrow
\text{更好的在线选择和定价}
\rightarrow
\text{更高净利润}
\rightarrow
\text{更接近完全信息上界}.
]

## 最终执行方案

你的案例可以求出完全信息净利润上界，建议采用以下固定设计：

> 从当前RC测试种子中生成8、12、16和20请求的子实例；每名乘客保留居家上车和最近2—3个集合点；固定MNL的Gumbel效用扰动；在相同价格边界、车辆容量和运营成本参数下，联合优化价格、乘客选择、车辆分配和最终路线；使用精确MIP求解器获得最优净利润或求解器best bound；最后比较Static、DSPO和DRPO距离该上界的gap。

**当前完整RC无需改动，也不需要重新训练全部模型。需要新增的是一个small-RC exact-oracle实验模块，并让DSPO、DRPO与Oracle在完全相同的小规模测试场景上运行。**
